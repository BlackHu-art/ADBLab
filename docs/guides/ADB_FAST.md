# ADB 执行环境自动适配

## 应用内自动选择

正常启动 ADBLab 后，在事件循环中安排后台环境检测。程序优先复用本机已运行的 ADB 服务，
服务可用即开始设备发现；先验证在线设备的 shell 双流和退出码，再完成原生耗时比较。
测速期间发现的新设备优先验证能力：唯一探测线程暂停当前只读原生基准，验证新目标后继续
基准；被暂停的测速不写入后端偏好，也不重放业务命令。
服务尚未就绪或已失效时，连接首试保留完整 3 秒，避免 Windows 延迟返回的连接拒绝被误判为
超时；提前超时或传输中断时，最多使用剩余预算复核一次。已就绪服务的轻量健康检查仍为
1 秒；显式重测已就绪服务、首次验证或显式重测设备能力时，首试 1 秒，超时或传输中断才复核一次，
两次共用 3 秒预算。取消、协议不兼容和已被替换的连接不重试。每轮对同一设备连接状态只验证一次，
避免多台持续超时的设备反复到期，导致一轮检测无法结束；新连接仍优先验证。
原生对照每条最多等待 2 秒，超时只作为耗时下界，不表示设备故障。只有运行实例首次初始化的
连接明确被拒绝时，才尝试启动一次本地服务，此启动另有 30 秒预算，并显示“正在启动本机
ADB 服务”；完成后以实际服务响应确认结果。扫描与业务命令的原有预算不受此影响，后续
自动检查及重新测速不重复启动或重启服务。

主机验证尚未完成时，手动刷新和后台扫描先等待这次检测，不并行启动另一个原生设备列表查询。
服务能力可用即继续发现，不等待后续原生测速；验证失败后才按既有策略选择原生。等待计入
原查询的总预算，后台扫描仍共用 15 秒，预算耗尽不再追加一次原生调用。取消、关闭或用户
切换到手动原生会及时结束等待；自定义 ADB 服务端点继续使用原有原生入口，而客户端来自内置、
`ADB_PATH` 还是 Android SDK，都按同一解析路径准入直连。

正式实现位于 [协议模块](../../core/adb_transport.py)、
[运行实例](../../core/adb_runtime.py)、[Qt 适配器](../../adblab/presentation/qt_adb_runtime.py) 和负责
开发控制台诊断的 [utils/adb_debug.py](../../utils/adb_debug.py)。
业务短命令仍通过 [CommandRunner](../../core/exec.py) 返回原有 `CommandResult`。直连为每次请求
建立独立短连接，并关闭 Nagle（TCP_NODELAY），避免小请求—小响应被合并写放大延迟。

| 操作 | 当前执行方式 |
| --- | --- |
| 设备列表和后台发现 | 在原生 ADB 与服务直连之间选择；快速扫描不被普通短命令忙碌状态阻塞 |
| 指定设备的普通非交互 shell | 首次能力验证通过即允许服务直连；原生对照完成后按耗时收益保留或切回原生 |
| 用户自定义 Shell、需要输入/PTY、特殊参数 | 原生 ADB |
| 固定 svc 开关、一次性日志导出/清空 | 经校验的设备 shell；按设备策略选择执行后端 |
| MobilePerf 同步短查询与 CPU 单次 top | 独立验证设备能力，运行中同步主窗口选择模式，保留采样器的原始文本转换 |
| 截图 `exec-out screencap -p` | 按设备策略选择原生 ADB 或服务直连，二进制输出直接写文件 |
| Remote 按键与手势 | 已验证设备优先执行直连短命令；原生模式复用持久输入 shell |
| scrcpy 4.1 启动 | 默认本机服务、当前设备已验证直连、版本 4.1、用户未追加参数且未设置 `SCRCPY_SERVER_PATH`、专用入口与服务端文件均可用时，通过独立 CLI 连接已有服务；其他情况启动前选定原生 ADB |
| 安装、传输、其他二进制命令、长期日志/录屏/Monkey | 保留原有执行边界 |

自动比较使用相同只读探针，不重复运行用户操作。首次属性请求最多短等 0.5 秒已排队的能力验证，
等待包含在原命令预算内。快速查询结果与原生路径共用输出、错误和超时转换；非零远端退出码
不会触发后端重试。相近耗时保留原生兼容路径；原生完成且双流/退出码一致时，要求
`快速耗时 + 20 毫秒 < 原生耗时 × 0.8`；原生探针超时时使用
`快速耗时 < 已等待时长 × 0.8` 比较耗时下界，不能据此判定原生更快。原生基准异常或输出
不符合只读探针契约时保留已验证能力及原有偏好，并记录本轮已尝试测速，轻量健康检查不重复
无效基准。只有初次比较准备改选原生时，才追加一次快速热态样本；热态结果有效且仍无收益
才改选原生，避免将打包环境的首次响应延迟固化为整次运行的偏好。

设置页的 **ADB 维护** 区是单列三张卡：**ADB 客户端**、**ADB 执行环境**、**重启本机 ADB 服务**。
**ADB 客户端** 折叠态显示当前选择，展开后按需识别本机 ADB 环境：只列出**实际配置的**来源（应用内置、环境变量
ADB_PATH、系统 PATH），未配置的来源不占位，已配置但不可用的来源保留并标注原因（文件不存在、
无法执行、超时、不是 ADB 程序），另提供 **自定义 adb**（文件选择器）与 **重新识别本地 ADB 环境**。Android SDK
的三个位置仍留在自动解析链里兜底，但不参与展示与版本探测，避免冷启动时逐个启动多个 adb 客户端。
识别只在后台串行运行 `adb version`（单项 3 秒预算、可取消），不连接 5037 服务；识别期间
只锁「重新识别」按钮，候选选择与自定义文件始终可用，超过 15 秒未回填则提示「识别超时，可重试」，
晚到结果仍会正常回填。**选择即时生效**：写入 `adb_client`、清空解析与短命令两层缓存并触发
重新检测；所选客户端缺失或无法执行时按选择如实失败，不静默换用其它 adb。设置页构建后会空闲预热
一次识别，展开卡片时通常已能看到结果。

**ADB 执行环境** 折叠态是状态行加常驻的 **重新检测** 按钮（模式：自动选择 · 设备列表：快速直连 ·
设备 Shell 2/3 台已验证 · 执行环境已就绪；无设备时显示「设备 Shell 未检查」，与设置里的
「持续扫描设备」不是同一件事），展开后是 **执行模式** 三选一；**重启 ADB** 使用**当前选择的 ADB 客户端**执行 kill-server/start-server，
会中断当前连接与投屏，成功后自动作废运行时能力并重新检测；切换客户端后可用它让新客户端接管
本机 5037 服务。执行模式只影响后续命令：自动模式按服务能力与测速结果选择；
手动快速跳过测速偏好、优先 5037 直连，但仍需通过能力验证；手动原生全部启动 adb.exe 客户端。
能力尚不可用时由状态行说明当前实际走原生及原因，不再改动用户选择。检测期间保留上一次稳定结果。

**重新检测** 恢复自动选择并重新验证，检测期间的后续手动选择不会被晚到结果覆盖。Qt 收到
后台通知后重新读取最新状态，不渲染排队的旧快照。选择只影响本次运行的后续命令，不写入
设置文件，不中断或重放已经发送的命令。

能力是否有效与测速偏好分开记录，策略按设备与 transport_id 失效。暂时失败只关闭对应能力；
轻量验证恢复后复用仍有效的测速偏好，不在每次轮询中重做所有原生基准。自动模式下，能力正常
且原生更快的设备保持原生选择，不被当作失败设备反复测速。故障使相应状态修订号失效，旧探针、原生
基准和晚到业务结果不能覆盖新的恢复状态。
成功设备列表若在返回时已被新的拓扑或显式重新检测取代，则标记为过期；扫描保留当前列表与
发现状态并等待下一轮，不把过期结果当作连接故障，也不重放业务命令。
手动刷新被取代时按取消结束，并恢复仍在等待的刷新前状态；已经收到的新快照不受该通知影响。

扫描在普通命令忙碌判断前提交后台检查；自动或手动快速模式的合法业务请求也可提交同一检查，因此关闭
持续扫描后的手动刷新、Shell 和截图仍能触发恢复。服务与各设备分别按 10 秒最小间隔节流，
并发触发复用唯一探测线程。实际恢复发生在到期后的下一次扫描或业务请求，不保证 10 秒内
完成；没有请求时不新增常驻轮询。手动原生模式不因业务或扫描启动自动探测，显式重新检测
恢复自动选择。诊断只记录能力、耗时、选择原因和恢复结果，不记录设备标识；运行时 INFO
经现有有界诊断队列后台保存，打包模式也可查看，正常检测不触发应用异常通知。源码额外保留
DEBUG 控制台输出。

只支持默认本机服务；设置了自定义服务器环境或特殊全局参数时保留原生执行，不能将命令静默
转发到默认端点。命令里的可执行文件与当前解析出的客户端不一致时同样保留原生，避免把请求
发给未经能力验证的其它 adb 副本。服务连接建立后的故障不回退重放；仅连接明确
被拒绝且命令未发送、未取消时允许原生回退一次，两条路径共用总超时。设备命令自身的超时
不会直接判定快速后端性能退化。

关闭时停止探测、取消已有快速请求，随后仍允许既有任务执行必要清理；生产者收口后最终封闭
运行实例。探测线程和活动连接由应用关闭监督流程跟踪，不将 socket 伪装为 `Popen`。
文件短命令 worker、快速扫描及应用管理的列表、详情和权限只读查询已接入执行中取消；
模型中的明确只读查询通过 `_run_readonly()` 合并关闭信号，原生客户端同样可以取消。
关闭控制器在后台等待 Executor、模型线程池及活动短命令，超过窗口关闭预算的任务仍报告
残留。写操作继续沿用自身完成和清理契约，不因只读优化统一中断。

设备概览的批量查询及格式兼容回退共用默认 15 秒预算；超时、离线或取消后停止补查。同一拓扑
的并发刷新合并为一个执行任务和一次待处理刷新，逐台完成即发布。写盘在后台串行，并在取得
写锁后复核代次，避免旧批次覆盖新记录。

应用详情首载用一次 `dumpsys package` 同时生成详情和权限；权限修改后的刷新仍重新查询。
Logcat 的 PID 查询和前台包探测向执行器传递取消，前台包的兼容探测共用总预算。
短探针通过 `core/adb_query.py` 只读缓存能力选择预算，不触发额外能力检测：就绪快速查询保留
5 秒上限，原生或冷状态通常预留 15 秒；每个调用仍受其已有总截止时间约束，不因兼容查询延长。
性能页获取当前应用、系统只读查询及 Monkey 前台探针均传递所属任务的取消或模型关闭。
Remote 启动预检默认共用 20 秒预算，版本、响应、尺寸及可选编码器查询均可取消；启动路径
不再等待附加的 `dd` 测速。

系统工具的固定 svc 按钮使用独立的服务/动作白名单，任意自定义 Shell 保留原生边界。
一次性日志命令保留主机 `ANDROID_LOG_TAGS` 过滤设置并作为设备 shell 值引用；持续日志仍为
原生长进程。Monkey 启动前清日志失败会停止该次启动，不掩盖失败或重复执行。
设备概览和系统工具的模式重启均区分请求提交与设备启动完成；模式重启原生命令预留 30 秒，
超时报告结果未知并要求刷新核实，不把超时当成功或自动重发。

### 查看实际 ADB 路径与执行后端

正常源码启动时，ADB 路径与执行诊断通过现有 `LogService.write_developer_console`
按日志级别输出，可直接在 PyCharm 的 Run / Debug 窗口查看 `[ADB]` 日志，无需启动
参数，也不新增日志文件。DEBUG、INFO 使用标准输出，警告与错误使用标准错误流，避免
普通诊断在 IDE 中全部显示为红色。打包运行继续沿用现有脱敏诊断策略，不输出这些完整路径日志。

以下 `[ADB]` 输出同样受设置项 `console_log_level` 控制：INFO 摘要需要阈值不高于
`INFO`，DEBUG 明细需要 `DEBUG`；阈值调高后 ADB 诊断会安静下来，但业务流程与诊断文件
不受影响。

首次解析完成时，INFO 摘要明确显示“已选择 ADB 客户端”、完整路径和中文来源；后续缓存
读取保留 DEBUG 记录，不重复输出 INFO。找不到客户端时输出 WARNING，不宣称选择成功。
启动后，实际模式切换、每轮检测开始/结束和每次命令调用仍输出 INFO：模式摘要同时显示
客户端路径与设备列表选路，检测摘要包含状态和快速 Shell 数量，调用摘要说明本次使用
原生客户端还是快速直连。能力不足时不把“优先快速”显示为已执行快速；原生测速仅描述
本次调用，不代表全局模式切换。重复点击同一模式不产生新的切换事件，关闭探测不输出
正常完成摘要。
在 PyCharm 或支持 ANSI 的终端中，选中路径的 INFO 摘要为青色，DEBUG 明细为灰色，
未找到客户端的 WARNING 为黄色；重定向到文件时保留纯文本，不写入颜色控制码。

`resolve_candidate` 按顺序显示每个候选的来源、路径和存在性，`resolve_result` 显示最终
选择及 `bundled`、`runtime_cache`、`env`、`sdk`、`PATH` 或 `missing` 来源；候选顺序为
Windows 内置 → `ADB_PATH` → Android SDK platform-tools → PATH，非 Windows 不使用内置
Windows 二进制。解析结果有进程内缓存，「重新检测」会先清缓存再重扫，安装或移除
platform-tools 后无需重启应用。正常 Windows onedir 的资源根是
`sys._MEIPASS` 指向的 `_internal`，因此候选路径为 `_internal\scrcpy-win64\adb.exe`，
不依赖启动命令所在目录。已缓存的路径也会明确标记，避免误认为每次都重新查询 PATH。

`probe_start` / `probe_result` / `probe_complete` 显示检测所用客户端路径、本机服务端点、
状态与耗时，并在探测结束时汇总当前策略；
`mode` 记录用户选择；`execute` 区分 `native_client` 和 `server_direct`。直连事件中的
客户端路径只是所适配的解析路径，`client_spawned=false` 表示该请求没有启动 adb.exe。
这里记录的是实际选路，不推断现存 ADB Server 是由哪份 adb.exe 启动。

开发控制台日志保留应用和 ADB 的完整路径，仅记录命令类别，不记录设备序列号、环境
变量值、完整 Shell 参数或命令输出；不修改执行模式、服务状态或用户配置。
旧 `LogService.log()` 各级别调用继续进入开发控制台，通用消息按既有诊断边界脱敏；
`[CMD]` 仍是达到 `performance_log_threshold_ms` 后才打印的慢命令摘要，不代表所有调用。

## Remote 投屏与输入

每台投屏在启动前冻结配置与 ADB 后端。独立入口
[scrcpy_adb_bridge.py](../../scripts/scrcpy_adb_bridge.py) 仅通过 scrcpy 子进程的 `ADB` 环境变量
传入，不修改全局环境或系统监控。它只支持已有服务验证、设备列表、固定 scrcpy-server 上传、
本会话端口转发和 scrcpy 4.1 的长连接 `app_process`；普通文件传输仍走原边界。
入口仍只接受 scrcpy 的固定上传与 CLASSPATH 参数，内部按会话身份映射到独享的临时 JAR；
同一手机的 USB/无线连接并发启动时，不会因共享默认 JAR 被另一会话删除而相互影响。
上传前登记清理意图，官方 server 根据自己的 CLASSPATH 删除文件；启动失败或部分上传时，
应用后台只删除本会话派生的精确文件名，不开放任意远端删除命令。
只有默认本机服务、当前设备已验证直连、版本 4.1、无额外参数且工具和服务端文件存在时使用。
选择原生 ADB、自定义服务或 scrcpy 服务端路径、不同版本或缺少专用入口时，在任何 scrcpy 业务请求前选定原生路径。
专用入口执行失败后不再启动原生 ADB 重试，避免重复上传或运行服务端。

专用协议逐帧转发 stdout/stderr 并传递退出码，握手和上传有预算，运行期保留取消检查。
普通界面启动由服务为每台投屏分配独立本机端口，跨服务实例保留到清理完成，原生模式同样适用。
这避免 Windows scrcpy 的 `SO_REUSEADDR` 让多个实例同时监听默认端口；显式自定义端口保持原配置。
每次快速投屏在用户数据目录创建独立会话，第一次合法隧道原子绑定 scrcpy 自己生成的 scid；
转发使用 `norebind`，删除前核对归属，不能移除其他投屏的端口。helper 观察 scrcpy 父进程
及应用进程，父进程消失即取消连接；操作系统文件锁登记存活 helper。后台清理等待租约释放，
只清理本会话映射和临时 JAR；失败记录脱敏日志并保留会话与端口归属，允许继续停止重试。
源码先按 [构建指南](BUILD_AND_RUN.md#scrcpy-专用-adb-入口) 构建专用入口；源码摘要变化后
旧入口不再被选择。正式产物随包提供独立 console onedir 工具，避免每条命令启动主 GUI 或重复解压。

输入后端按当前设备能力读取，不触发新探测。直连预热只报告已验证能力，不启动原生 shell；
输入返回远端实际结果。原生持久 shell 的成功写入仍不等于设备执行确认，写入/刷新失败后不
重发，异常清理也不再次刷新可能保留输入的缓冲。仅在预热失败且用户输入尚未发送时允许有界
兼容执行。关闭取消贯通按键、手势尺寸查询和输入链；改选设备不改向已经开始的操作。

## 截图采集与浏览

截图沿用 `CommandRunner.run_to_file()`，只对明确指定设备的 `exec-out screencap -p` 开放
快速二进制通道；通过已验证的 shell v2 raw 流接收原始字节，stderr 和退出码独立处理。
不扩大其他 `exec-out` 或文件传输命令的适用范围，设置页选择的执行模式与客户端同样作用于后续截图。

每次采集共用 30 秒预算，在目标目录创建独占临时文件，工作线程检查 PNG 首尾并完整解码，
成功且未取消才原子替换最终路径。取消、超时、坏图、设备断开和本地写入失败不发布半张图片，
保留已有目标文件并清理临时文件；Controller 的批次取消与 model 关闭均传入执行中取消检查。
若临时文件被占用导致清理失败，保留原始采集失败结果，另外记录不含路径的清理诊断。
只有客户端明确不识别 `exec-out` 时才尝试远端文件兼容路径，该路径使用任务独占文件名，
在剩余预算内尝试拉取和删除，不再因空输出、坏图或传输中断重复拍摄。

截图页将文件名、圆点与数量、缩放比例叠放在画布左上、左下和右下，扩大图片可用高度；
窄窗口会省略长文件名并减少可见圆点。命令栏提供“删除全部”，删除当前图库加载的全部文件，
包括添加的本地图片；右键菜单保留单张删除。已不存在的文件移出图库，删除失败的文件继续
保留并提示失败数量，主图、分页和空态同步更新。

图片通过页面独占线程解码为 `QImage`，GUI 线程收到当前图后立即创建 `QPixmap`，邻图继续
后台预读。页面像素缓存上限为 64 MiB，按文件路径、修改时间及大小校验；超出上限的单图
只保留当前预览。新增批次增量追加列表和圆点，隐藏页不为接收结果启动解码。
“删除全部”在受监督线程中处理触发时的快照；新到图片不加入该任务，同路径新批次使尚未
执行的旧删除失效。取消停止剩余项，已进入的文件系统调用仍需等待结束；页面只在原生线程
完成 join 后释放，不把 `finished` 信号等同于资源已退出。

## MobilePerf 采集进程

[MobilePerfRunner](../../services/mobileperf_runner.py) 启动 worker 时，通过子进程环境传递
统一解析的 `ADB_PATH` 和 `MOBILEPERF_ADB_MODE`（`auto` / `fast` / `native`）。后者继承
启动时的选择模式；每次采集独占 `MOBILEPERF_ADB_MODE_FILE` 指向的临时模式文件。父进程
后台约每 100ms 检查模式变化，用同目录临时文件原子发布；首次文件尚未就绪时使用启动环境。
采集器在后续短命令准入时应用模式，仍独立验证自己的设备能力，不重启采集、不重放在途命令，
不写入用户配置。缺失、损坏或非法模式保留最后一次有效选择，写入失败后台重试。模式线程
与输出管道共同收口后才通知完成并清理本次临时目录，旧运行不能写入新运行目录。
关闭监督同时跟踪各代模式线程；子进程已经退出但写入尚未结束时仍报告运行资源未释放，
停止按本次快照和既有等待预算收口，不把后来启动的新会话纳入旧停止请求。
直接运行 MobilePerf 命令行时默认自动选择，也可在该进程环境中指定 `fast` 或 `native`。

[采集执行器](../../mobileperf/android/adb_execution.py) 归 `StartUp.run()` 所有，经当前
`RuntimeData` 交给本次运行创建的 ADB 适配对象。每个 worker 只验证自己的目标设备，首次
能力等待最多 1.5 秒，原生对照仍在后台完成；后续命令有节流地检查拓扑，设备重新连接后
重新验证能力，不重复执行采样命令测速。未进入 StartUp 的独立 ADB 工具对象保持原生行为。

有限超时的同步 shell 复用核心双后端，保留 stdout 优先、空 stdout 使用 stderr、非零退出码、
原始换行与编码回退等采样契约。传输失败返回空样本并更新连接状态，不把诊断当成采样结果。
CPU 周期查询的 `top -n 1` 已改为有限超时、可取消的同步调用，CSV 格式及采样间隔计算不变。
FD 和线程数采集器共享本次运行、设备、目标包及周期的 PID/status 快照；下一周期重新查 PID，
支持应用重启。单独使用任一采集器时仍可自行查询。主循环与相关指标的间隔等待可以被停止事件
唤醒，主循环同时短周期检查 stop 文件，并按绝对截止时间限制采集等待。
`sync=False` 仍返回真实 Popen；合并输出流、无限等待、文件传输和长期进程保留原执行边界。

stop 文件、运行退出事件和 CPU 采集器自身的停止事件可取消同步查询，包括已选择的原生客户端。
重连后的 uptime 补查与当前同步查询共享一次预算和取消信号；预算耗尽后不再发起主查询。
异步进程入口延后补查，仍立即返回真实 Popen；显式无限等待的兼容语义保持不变。
进入收尾时，执行器停止探测、拒绝采集线程的新请求，并允许当前收尾线程继续查询和整理报告；
最终封闭时取消剩余请求并有界等待资源释放。启动提前返回和异常也经过最终清理。

## 独立命令入口

当每次 `adb version` 和设备命令都有明显的共同延迟，而现有 ADB 服务响应正常时，
可使用 [adb_fast.py](../../scripts/adb_fast.py) 直接连接本机 `127.0.0.1:5037`。
这个独立入口只依赖 Python 标准库，并复用正式协议模块；不修改 PATH 或监控策略。
脚本明确使用直连，不执行应用的后台速度比较，也不是完整的 adb 替代品。

## 使用

以下命令从仓库根执行。服务必须已运行；不可用时，先手动执行一次原生 `adb start-server`。

```powershell
.\.venv\Scripts\python.exe scripts/adb_fast.py devices -l
.\.venv\Scripts\python.exe scripts/adb_fast.py -s <设备序列号> shell echo ADBLAB_PROBE
.\.venv\Scripts\python.exe scripts/adb_fast.py -s <设备序列号> shell getprop ro.build.version.sdk
.\.venv\Scripts\python.exe scripts/adb_fast.py --timeout 10 -s <设备序列号> shell 'printf ADBLAB_ERR >&2; exit 7'
$LASTEXITCODE
```

用 `devices` 结果中的目标替换占位符；设备标识只在本机使用，不要提交到代码或诊断记录。
多设备时使用 `-s` 明确指定目标。未传 `-s` 时尊重 `ANDROID_SERIAL`；两者都没有时由 ADB
服务判定是否存在唯一设备，不自动挑选第一台设备。全局选项放在 `devices` 或 `shell` 前。

也可以在当前 PowerShell 会话定义一个便捷函数，无需写入 profile 或改全局配置：

```powershell
$adbFastPython = (Resolve-Path .\.venv\Scripts\python.exe).Path
$adbFastScript = (Resolve-Path .\scripts\adb_fast.py).Path
function adbf { & $adbFastPython $adbFastScript @args }
adbf devices -l
adbf -s <设备序列号> shell getprop ro.build.version.sdk
```

## 支持范围与失败语义

- 支持 `devices [-l]` 和具有明确命令的非交互 `shell`，要求设备支持 shell v2。
- shell 的 stdout、stderr 分流输出，原样返回远端退出码；不缓冲整份输出。
- 不读取 stdin，不分配 PTY；需要交互终端、输入流或 `shell -t/-x` 等选项时使用原生 adb。
- `push`、`pull`、`install`、`exec-out`、`connect` 等命令不支持，明确报错，不自动转交执行。
- 采用与原生 `adb shell` 相同的空格拼接规则。复合命令和动态值仍需调用方正确引用；
  这个入口不会额外替用户转义或保证任意 shell 命令只读。
- 默认网络总超时 30 秒，使用 `--timeout` 调整；持续收到输出不会重置截止时间。
  超时返回 124，Ctrl+C 返回 130，连接/协议错误返回 1，参数错误返回 2。
- 超时、断线、取消和协议错误均关闭连接，不重试、不回退，避免执行结果未知时重复操作。
  关闭本地连接不能保证设备端已脱离 shell 会话的后台程序被终止；此时远端完成状态未知。
- 不自动启动、重启或停止 ADB 服务，不新增后台守护进程。每次请求都有自己的短连接。
- 设置了 `ADB_SERVER_SOCKET`、`ANDROID_ADB_SERVER_ADDRESS` 或 `ANDROID_ADB_SERVER_PORT`
  时拒绝执行，避免将本应访问其他服务的命令静默发到默认服务；此类环境使用原生 adb。
