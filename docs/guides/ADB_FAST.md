# ADB 执行环境自动适配

## 应用内自动选择

正常启动 ADBLab 后，在事件循环中安排后台环境检测。程序优先复用本机已运行的 ADB 服务，
服务可用即开始设备发现；先验证在线设备的 shell 双流和退出码，再完成原生耗时比较。
测速期间发现的新设备优先验证能力：唯一探测线程暂停当前只读原生基准，验证新目标后继续
基准；被暂停的测速不写入后端偏好，也不重放业务命令。
原生对照每条最多等待 2 秒，超时只作为耗时下界，不表示设备故障。只有运行实例首次初始化的
连接明确被拒绝时，才尝试启动一次本地服务；后续自动检查及重新测速不重复启动或重启服务。

正式实现位于 [协议模块](../../core/adb_transport.py)、
[运行实例](../../core/adb_runtime.py) 和 [Qt 适配器](../../adblab/presentation/qt_adb_runtime.py)。
业务短命令仍通过 [CommandRunner](../../core/exec.py) 返回原有 `CommandResult`。

| 操作 | 当前执行方式 |
| --- | --- |
| 设备列表和后台发现 | 在原生 ADB 与服务直连之间选择；快速扫描不被普通短命令忙碌状态阻塞 |
| 指定设备的普通非交互 shell | 能力验证通过且有明显耗时收益时走服务直连 |
| 用户自定义 Shell、需要输入/PTY、特殊参数 | 原生 ADB |
| MobilePerf 同步短查询与 CPU 单次 top | 独立采集进程初始化自动执行策略，保留采样器的原始文本转换 |
| 截图 `exec-out screencap -p` | 按设备策略选择原生 ADB 或服务直连，二进制输出直接写文件 |
| 安装、传输、其他二进制命令、长期日志/录屏/Monkey | 保留原有执行边界 |

自动比较使用相同只读探针，不重复运行用户操作。首次属性请求最多短等 0.5 秒已排队的能力验证，
等待包含在原命令预算内。快速查询结果与原生路径共用输出、错误和超时转换；非零远端退出码
不会触发后端重试。相近耗时保留原生兼容路径，原生完成时要求快速路径至少快 20% 且超过
20 毫秒；原生探针超时时按耗时下界比较。

设置页的 **ADB 维护** 区显示设备发现与 Shell 的适用范围，提供 **重新检测** 和
**使用原生 ADB** 开关。开关只影响本次运行的后续命令，不写入设置文件，不中断当前命令。
能力是否有效与测速偏好分开记录，策略按设备与 transport_id 失效。暂时失败只关闭对应能力；
轻量验证恢复后复用仍有效的测速偏好，不在每次轮询中重做所有原生基准。能力正常且原生更快
的设备保持原生选择，不被当作失败设备反复测速。故障使相应状态修订号失效，旧探针、原生
基准和晚到业务结果不能覆盖新的恢复状态。
成功设备列表若在返回时已被新的拓扑或显式重新检测取代，则标记为过期；扫描保留当前列表与
发现状态并等待下一轮，不把过期结果当作连接故障，也不重放业务命令。
手动刷新被取代时按取消结束，并恢复仍在等待的刷新前状态；已经收到的新快照不受该通知影响。

扫描在普通命令忙碌判断前提交后台检查；合法的自动模式业务请求也可提交同一检查，因此关闭
持续扫描后的手动刷新、Shell 和截图仍能触发恢复。服务与各设备分别按 10 秒最小间隔节流，
并发触发复用唯一探测线程。实际恢复发生在到期后的下一次扫描或业务请求，不保证 10 秒内
完成；没有请求时不新增常驻轮询。原生模式不因业务或扫描启动自动探测，显式重新检测保留
原生选择。诊断复用现有日志，只记录后端选择原因、能力等待和恢复结果，不记录设备标识。

只支持默认本机服务；设置了自定义服务器环境、特殊全局参数或指定了其他 ADB 可执行路径时
保留原生执行，不能将命令静默转发到默认端点。服务连接建立后的故障不回退重放；仅连接明确
被拒绝且命令未发送、未取消时允许原生回退一次，两条路径共用总超时。设备命令自身的超时
不会直接判定快速后端性能退化。

关闭时停止探测、取消已有快速请求，随后仍允许既有任务执行必要清理；生产者收口后最终封闭
运行实例。探测线程和活动连接由应用关闭监督流程跟踪，不将 socket 伪装为 `Popen`。
文件短命令 worker、快速扫描及应用管理的列表、详情和权限只读查询已接入执行中取消；
模型中的明确只读查询通过 `_run_readonly()` 合并关闭信号，原生客户端同样可以取消。
关闭控制器在后台等待 Executor、模型线程池及活动短命令，超过窗口关闭预算的任务仍报告
残留。写操作继续沿用自身完成和清理契约，不因只读优化统一中断。

设备概览的批量查询及格式兼容回退共用默认 15 秒预算；超时、离线或取消后停止补查。同一拓扑
的并发刷新合并为一个执行任务和一次待处理刷新，逐台完成即发布。写盘在后台串行，并在取得
写锁后复核代次，避免旧批次覆盖新记录。

应用详情首载用一次 `dumpsys package` 同时生成详情和权限；权限修改后的刷新仍重新查询。
Logcat 的 PID 查询和前台包探测向执行器传递取消，前台包的兼容探测共用总预算。
Remote 启动预检默认共用 20 秒预算，版本、响应、尺寸及可选编码器查询均可取消；启动路径
不再等待附加的 `dd` 测速。

2026-09-07 四台实机通过正式运行实例和 model/worker 入口验证：服务约 0.024 秒可用，全部
快速 Shell 能力约 0.463 秒可用，原生对照约 10.51 秒完成。设备概览查询为 0.360～0.568 秒，
应用列表为 0.079～0.141 秒，文件 worker 查询为 0.037～0.077 秒；同一回显命令临时原生模式
为 6.265 秒，恢复自动选择为 0.047 秒。以上为本次环境测量，不是其他环境的性能保证。

## 截图采集与浏览

截图沿用 `CommandRunner.run_to_file()`，只对明确指定设备的 `exec-out screencap -p` 开放
快速二进制通道；通过已验证的 shell v2 raw 流接收原始字节，stderr 和退出码独立处理。
不扩大其他 `exec-out` 或文件传输命令的适用范围，设置页的原生开关同样作用于后续截图。

每次采集共用 30 秒预算，在目标目录创建独占临时文件，工作线程检查 PNG 首尾并完整解码，
成功且未取消才原子替换最终路径。取消、超时、坏图、设备断开和本地写入失败不发布半张图片，
保留已有目标文件并清理临时文件；Controller 的批次取消与 model 关闭均传入执行中取消检查。
若临时文件被占用导致清理失败，保留原始采集失败结果，另外记录不含路径的清理诊断。
只有客户端明确不识别 `exec-out` 时才尝试远端文件兼容路径，该路径使用任务独占文件名，
在剩余预算内尝试拉取和删除，不再因空输出、坏图或传输中断重复拍摄。

截图页将文件名、圆点与数量、缩放比例叠放在画布左上、左下和右下，扩大图片可用高度；
窄窗口会省略长文件名并减少可见圆点。命令栏提供“删除全部”，删除当前图库加载的全部文件，
包括添加的本地图片；右键菜单保留单张删除。已不存在的文件移出图库，删除失败的文件继续
保留并提示失败数量，主图、分页和空态同步更新。

图片通过页面独占线程解码为 `QImage`，GUI 线程收到当前图后立即创建 `QPixmap`，邻图继续
后台预读。页面像素缓存上限为 64 MiB，按文件路径、修改时间及大小校验；超出上限的单图
只保留当前预览。新增批次增量追加列表和圆点，隐藏页不为接收结果启动解码。
“删除全部”在受监督线程中处理触发时的快照；新到图片不加入该任务，同路径新批次使尚未
执行的旧删除失效。取消停止剩余项，已进入的文件系统调用仍需等待结束；页面只在原生线程
完成 join 后释放，不把 `finished` 信号等同于资源已退出。

2026-09-07 在四台实机上经正式截图 model 各采集三次，自动路径耗时为 1.09～1.30 秒，
均完成 PNG 解码且无临时文件残留；同一设备的原生路径为 7.95 秒，自动路径中位数为
1.12 秒。数据仅代表本次环境，不构成其他设备或环境的性能保证。

## MobilePerf 采集进程

[MobilePerfRunner](../../services/mobileperf_runner.py) 启动 worker 时，通过子进程环境传递
统一解析的 `ADB_PATH` 和 `MOBILEPERF_ADB_MODE`（`auto` / `native`）。后者继承启动当时
设置页的原生选择；运行中切换设置不会改变已有采集会话，下次启动时生效，不写入用户配置。
直接运行 MobilePerf 命令行时默认自动选择，也可在该进程环境中指定 `native`。

[采集执行器](../../mobileperf/android/adb_execution.py) 归 `StartUp.run()` 所有，经当前
`RuntimeData` 交给本次运行创建的 ADB 适配对象。每个 worker 只验证自己的目标设备，首次
能力等待最多 1.5 秒，原生对照仍在后台完成；后续命令有节流地检查拓扑，设备重新连接后
重新验证能力，不重复执行采样命令测速。未进入 StartUp 的独立 ADB 工具对象保持原生行为。

有限超时的同步 shell 复用核心双后端，保留 stdout 优先、空 stdout 使用 stderr、非零退出码、
原始换行与编码回退等采样契约。传输失败返回空样本并更新连接状态，不把诊断当成采样结果。
CPU 周期查询的 `top -n 1` 已改为有限超时、可取消的同步调用，CSV 格式及采样间隔计算不变。
FD 和线程数采集器共享本次运行、设备、目标包及周期的 PID/status 快照；下一周期重新查 PID，
支持应用重启。单独使用任一采集器时仍可自行查询。主循环与相关指标的间隔等待可以被停止事件
唤醒，主循环同时短周期检查 stop 文件，并按绝对截止时间限制采集等待。
`sync=False` 仍返回真实 Popen；合并输出流、无限等待、文件传输和长期进程保留原执行边界。

stop 文件、运行退出事件和 CPU 采集器自身的停止事件可取消同步查询，包括已选择的原生客户端。
重连后的 uptime 补查与当前同步查询共享一次预算和取消信号；预算耗尽后不再发起主查询。
异步进程入口延后补查，仍立即返回真实 Popen；显式无限等待的兼容语义保持不变。
进入收尾时，执行器停止探测、拒绝采集线程的新请求，并允许当前收尾线程继续查询和整理报告；
最终封闭时取消剩余请求并有界等待资源释放。启动提前返回和异常也经过最终清理。

## 独立命令入口

当每次 `adb version` 和设备命令都有明显的共同延迟，而现有 ADB 服务响应正常时，
可使用 [adb_fast.py](../../scripts/adb_fast.py) 直接连接本机 `127.0.0.1:5037`。
这个独立入口只依赖 Python 标准库，并复用正式协议模块；不修改 PATH 或监控策略。
脚本明确使用直连，不执行应用的后台速度比较，也不是完整的 adb 替代品。

## 使用

以下命令从仓库根执行。服务必须已运行；不可用时，先手动执行一次原生 `adb start-server`。

```powershell
.\.venv\Scripts\python.exe scripts/adb_fast.py devices -l
.\.venv\Scripts\python.exe scripts/adb_fast.py -s <设备序列号> shell echo ADBLAB_PROBE
.\.venv\Scripts\python.exe scripts/adb_fast.py -s <设备序列号> shell getprop ro.build.version.sdk
.\.venv\Scripts\python.exe scripts/adb_fast.py --timeout 10 -s <设备序列号> shell 'printf ADBLAB_ERR >&2; exit 7'
$LASTEXITCODE
```

用 `devices` 结果中的目标替换占位符；设备标识只在本机使用，不要提交到代码或诊断记录。
多设备时使用 `-s` 明确指定目标。未传 `-s` 时尊重 `ANDROID_SERIAL`；两者都没有时由 ADB
服务判定是否存在唯一设备，不自动挑选第一台设备。全局选项放在 `devices` 或 `shell` 前。

也可以在当前 PowerShell 会话定义一个便捷函数，无需写入 profile 或改全局配置：

```powershell
$adbFastPython = (Resolve-Path .\.venv\Scripts\python.exe).Path
$adbFastScript = (Resolve-Path .\scripts\adb_fast.py).Path
function adbf { & $adbFastPython $adbFastScript @args }
adbf devices -l
adbf -s <设备序列号> shell getprop ro.build.version.sdk
```

## 支持范围与失败语义

- 支持 `devices [-l]` 和具有明确命令的非交互 `shell`，要求设备支持 shell v2。
- shell 的 stdout、stderr 分流输出，原样返回远端退出码；不缓冲整份输出。
- 不读取 stdin，不分配 PTY；需要交互终端、输入流或 `shell -t/-x` 等选项时使用原生 adb。
- `push`、`pull`、`install`、`exec-out`、`connect` 等命令不支持，明确报错，不自动转交执行。
- 采用与原生 `adb shell` 相同的空格拼接规则。复合命令和动态值仍需调用方正确引用；
  这个入口不会额外替用户转义或保证任意 shell 命令只读。
- 默认网络总超时 30 秒，使用 `--timeout` 调整；持续收到输出不会重置截止时间。
  超时返回 124，Ctrl+C 返回 130，连接/协议错误返回 1，参数错误返回 2。
- 超时、断线、取消和协议错误均关闭连接，不重试、不回退，避免执行结果未知时重复操作。
  关闭本地连接不能保证设备端已脱离 shell 会话的后台程序被终止；此时远端完成状态未知。
- 不自动启动、重启或停止 ADB 服务，不新增后台守护进程。每次请求都有自己的短连接。
- 设置了 `ADB_SERVER_SOCKET`、`ANDROID_ADB_SERVER_ADDRESS` 或 `ANDROID_ADB_SERVER_PORT`
  时拒绝执行，避免将本应访问其他服务的命令静默发到默认服务；此类环境使用原生 adb。
