# Intent 调试与性能元数据实施计划

本计划记录用户批准的首批范围及验收依据，不替代现状知识库。

**目标：** 完成 Intent / Deep Link 参数入口与性能运行元数据，利用本地 Android 15 模拟器验收。

**架构：** Intent 使用不可变请求和现有异步 model、ActionResults 路由；性能在独立采集 worker
启动期写白名单元数据，后台产物查询按运行身份读取，GUI 只消费快照。复用 PySide6 与已有执行器。

**设计来源：** 本次会话中已批准的首批方案；后续 APK 安装、Perfetto、证据包不纳入本轮。

## 约束与验收

- 保留旧信号、Controller 调用和历史记录兼容；不升级生产依赖，不改现有存储 schema，不发布。
- 不在 GUI 查询设备或读写文件；不保存设备序列号或整个 dumpsys 文本到新增元数据。
- 校验组件、URI、flags 和广播 typed extras；无效输入不发送，动态参数通过 quote 边界。
- 结果归属、重复请求、失败、取消、晚到回调与关闭采用既有生命周期。
- 模拟器证明协议和数据流程，性能数值不代表真机性能。

## 实施与验证顺序

1. 在现有 System 分类测试上取得基线，补 Intent URI 误判、表单请求和 typed extras 失败测试。
2. 实现 `services/intent_request.py`、model / Controller 请求转换，System 内嵌模式与高级参数。
3. 补性能元数据解析、快照、损坏文件与跨运行归属测试；实现采样前写入和后台归档读取。
4. 运行各模块直接与关联测试；修改文件 Ruff、相关生产模块 Pyright、中文注释和文档检查。
5. 模拟器验证安全系统 Intent、无接收者失败和版本元数据；不运行压力操作，不安装业务应用。
6. 独立 agent 审查整批差异，修复发现，检查受影响入口的 packaging self-check。

测试使用本工作区隔离 `.venv`，继承已有运行依赖，仅安装项目固定版本测试工具。
无需将原仓库工作区、系统 Python 或用户配置作为测试输出目录。
