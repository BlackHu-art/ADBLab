# Windows 安装版应用内升级设计

状态：用户已授权核对计划后实施；本设计落实此前升级计划的未决边界。

## 范围与兼容性

仅启动时通过现有 InstallationGuard 的 Windows x64 安装版开放内置下载和交接。
源码、ZIP、其他平台以及缺少可信 setup 资产的正式版本继续使用浏览器入口。
不改变版本、AppId、配置 schema、数据目录和安装维护协议，不发布正式版本。

## 信任与下载

固定官方 GitHub latest API 的同一次成功响应提供版本、资产 ID、大小和 SHA-256。
仅接受 `ADBLab-win-x64-v{version}-setup.exe`，资产必须 uploaded、唯一且不超过 2 GiB。
下载入口必须为该项目该 tag 的精确 HTTPS URL；最多三次跳转，只允许 HTTPS/443 的
`release-assets.githubusercontent.com`，不允许 userinfo、fragment 或降级 HTTP。
当前安装器没有发布者代码签名；此方案提供 GitHub/TLS 信任模型下的完整性。

独立 Qt 工作线程拥有网络、计时器和磁盘句柄，64 KiB 分块，30 秒传输停滞超时、30 分钟总期限。
缓存位于用户数据根的 `updates` 子目录，每次任务使用独占随机子目录。只有大小和摘要正确、
无重解析路径的普通文件才可原子发布为 ready；取消仅移除本次临时文件。重新检查版本会撤销旧结果准入。

## 退出与交接

下载完成后用户点击“退出并安装”，确认当前实例将按现有流程停止任务并保存数据。
先异步复制独立、仅标准库的 onefile helper 到本次缓存，启动并握手；失败时主窗口仍可正常操作。
helper 不运行主入口、不进入 ProcessRunner 全局表、不持有安装目录运行锁，运行闭包和 cwd 均在安装根之外。
stdin 私有管道传递绑定资产与父进程身份的请求及一次性 COMMIT；文件标记不授予执行权限。
helper 在 READY 前打开父进程 HANDLE 并核对创建时间，始终等待同一进程对象，不依据进程名或反复查询 PID。

现有关闭开始后不可逆，且失败时仍会退出；本期保持该行为。独立记录全部停止/落盘结果，
失败、超时、强制停止、注册准备异常或残留均禁止交接。根入口清理结束且安装锁释放成功后才发送 COMMIT。
helper 必须看到 COMMIT、父进程实际退出且退出码为 0，之后才启动交互式安装器；等待有界，绝不结束其他进程。
执行时重新校验文件，并以拒绝写入/删除的 Windows 文件句柄覆盖校验到 CreateProcess 的窗口。
安装器负责目录、版本、占用和维护身份判断；启动成功仅代表已交接。

关闭前失败可在当前窗口重试。关闭开始后失败保留缓存，下次启动并成功重新检查同一发布后可重新验证使用；
不重新启用已经关闭的监督器、设置和 Controller。安装器取消或拒绝仍由既有恢复方案处理。

## 验收边界

资产、Qt 下载、取消、磁盘/TLS/重定向失败、缓存替换、关闭授权、根入口异常和原生父进程等待均需回归。
冻结 helper 必须实际构建并验证不依赖安装目录；新增收集入口验证源码与冻结 packaging。
目前正式 v3.3.2 仅有 ZIP，没有旧/新正式 setup 对，因此不得宣称已完成真实正式安装包之间端到端升级。
可用一次性测试载荷验证真实进程与交接，并明确它与正式升级证据的区别。
