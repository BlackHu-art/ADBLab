# 无线 ADB 配对界面交互规格

日期：2026-09-25。状态：本轮实现依据，尚不表示界面或实机验收通过。

本规格补充[扫码配对实施设计](2026-09-25-wireless-adb-pairing-design.md)，只细化交互与界面。
协议、进程归属、身份确认及取消边界继续以该设计为准。本轮用户已要求按方案实现，并明确要求
独立 agent 设计交互；不重复设置设计批准门禁。

## 2. 用户目标与入口

用户在设备总览点击“连接设备”，可以沿用 IP 地址连接，也可用 Android 11+ 无线调试扫描器完成
首次配对。窗口需要清楚区分“已接受配对”和“已经能执行 ADB 命令”，在发现失败时提供实际可用
的手动入口。

采用一个由 MainFrame 持有的 **非阻塞、非模态 FluentDialog**：

- 标题“连接设备”，有标准标题栏关闭按钮；用 `show()`，不调用嵌套 `exec()`。
- 默认页为“地址与历史”，另外两页为“扫码配对”和“配对码”。普通打开窗口不启动发现。
- 同一 MainFrame 至多有一个已打开或正在清理的连接窗口。重复点入口仅激活现有窗口，保留输入。
- 成功扫码不自动选择操作设备，不自动打开工具页。设备列表按既有刷新链更新。
- 普通关闭后，待资源退出才销毁窗口并清空 MainFrame 引用。下次打开重新创建，确保主题订阅有效。
- 连接窗口允许用户回到主窗口调整 ADB 客户端；上下文失效后窗口必须明确停止旧会话。

## 3. 布局与控件

### 3.1 外壳

初始尺寸 **640 × 680 个逻辑像素**，以宿主屏幕 `availableGeometry` 减去四周 24 像素为上限；
不把该尺寸写成固定最小高度。建议最小宽度 360；屏幕可用宽度不足时继续按屏幕收缩。
内容可纵向滚动，标题栏、页导航及底部关闭动作始终可达。小屏的最低高度同样受可用屏幕限制。

- 外部内容边距 24，小于 480 宽时为 16；组间距 20，字段间距 8，相关控件间距 12。
- 标题栏空间仅由 `finalize_fluent_layout()` 追加，不能手工重复预留 48 像素。
- 导航使用现有 `AdaptiveNavigation`，名称“连接方式”。正常显示 Fluent Pivot，放大字号或
  窄窗口时自动变成下拉框；不用三个固定宽度按钮模拟页签。
- 页面用 `QStackedWidget` 配合 `SmoothScrollArea` 承载，页面最小宽度为 0；不要让隐藏页的
  `minimumSizeHint` 反向撑大整个窗口。优先单列布局，避免为一张二维码引入响应式双栏系统。
- 各页说明使用 `BodyLabel`，小提示用 `UI_SMALL`，组标题用 `StrongBodyLabel`；所有文案经 `tr()`。
  统一应用 `BaseStyles` 字体角色，不能保留 Fluent 默认固定字号。
- 输入和按钮高度至少 `max(32, fontMetrics.height() + 16, minimumSizeHint.height())`，解除固定
  `maximumHeight`。不设固定文本高度，不把英文或大字号截成省略号。
- 底部为可换行的按钮区：左侧状态相关次动作，右侧“关闭”或“完成”。不将关闭做成强强调按钮。

扫码页结构如下；括号内为说明，不是界面文字：

```text
连接设备                                                    ×
地址与历史    扫码配对    配对码

使用手机的无线调试扫描器
手机与电脑连接同一局域网。
1  打开“开发者选项 → 无线调试”
2  选择“使用二维码配对设备”
3  扫描下方二维码，保持此页面打开

                    ┌────────────────┐
                    │                │
                    │    二维码      │
                    │                │
                    └────────────────┘
                    二维码将在 1:59 后过期

等待手机扫码
找不到扫描入口时，可以使用配对码。

刷新二维码       使用配对码                    取消本次    关闭
```

按实际窗口宽度把次动作移至二维码下方或换成两行，不通过缩小字体塞进一行。主动作始终只有一个：
等待扫码时二维码是主入口，不再放一个无意义的“开始连接”；停用或终态时主动作为“生成二维码”、
“重新生成”或“完成”。

### 3.2 地址与历史页

直接嵌入 `DeviceConnectionForm`，沿用其历史 `userData`、地址规范化、错误提示和回车提交。
首版允许其已有页内“连接设备”小标题，避免为视觉去修改共享旧组件。页面导航已说明用途，
不再新增第二层说明卡或新的历史列表。

现有 `DeviceContextBar.open_connection()` 会在有效地址提交后关闭浮层。新窗口保持此语义：
有效提交一次地址 → 立即禁用重复提交 → 通过原控制器路径连接 → 关闭窗口，结果由原主窗反馈。
不得为此页订阅全局 `operation_completed` 并把别处的 connect 结果误当扫码状态。
校验失败保持窗口并聚焦地址；无历史时显示空输入，不渲染“加载中”。

### 3.3 扫码配对页

首次进入且资源空闲时开始一轮环境检查。检查成功后才显示二维码，并从图像真正可见时开始
120 秒有效期倒计时。检查阶段用相同区域的 Fluent 不定进度环和“正在准备扫码”，避免布局跳动。

二维码目标边长约 240–280 个逻辑像素；最终由模块数和当前设备像素比选择整数物理像素倍数，
居中显示。白色底、黑色模块、至少 4 模块静区，无 Logo、阴影、圆角遮罩及平滑缩放。
深色主题下仍保持白底黑码。跨屏设备像素比改变时从当前内存数据重绘，不启动新会话。

扫码提示固定使用手机开发者选项路径，不能写“用相机/微信扫一扫”。可见二维码没有“复制”“保存”
按钮，禁止图片上下文菜单导出；`accessibleName` 只写“无线调试配对二维码”，不含载荷。

发现本轮手机后立即移除二维码及倒计时，显示“正在配对”。这时用户不应继续拿旧二维码配第二台。
不能在旧码上仅叠一层半透明状态，因为仍可能被扫描。

### 3.4 配对码页

两个有永久标签的输入，禁止仅靠占位符说明：

| 字段 | 组件与文案 | 行为 |
| --- | --- | --- |
| 配对地址 | Fluent `LineEdit`；占位符 `192.168.1.10:37123` | 接受经过现有边界校验的 IPv4:port、[IPv6]:port；不默认填 5555 |
| 配对码 | Fluent `LineEdit`，密码回显；占位符“手机显示的 6 位数字” | 允许粘贴；仅接受 ASCII 六位数字，保留前导零；提交前不转整数 |

上方说明：“在手机‘无线调试’中选择‘使用配对码配对设备’，填写其中的地址和配对码。”
紧接配对地址的小提示：“这里使用配对弹窗里的端口。”

主按钮“配对并连接”。仅字段均有效且协调器空闲时启用；提交时仍再次校验，失败聚焦首个错误字段。
配对码支持回车提交；其他页的默认按钮不能响应这里的回车。请求被受理后将输入框中的配对码清空，
服务层仅保留执行所需那一份；结束、切页、关闭、客户端失效时再次清空。
配对地址在同一窗口的重试中保留，口令不保留；配对地址不写入连接历史。

不要求用户开始时同时填写连接端口。需要手动续连时再展示下一节的字段，避免第一次使用就分不清
两个端口。

## 4. 状态呈现与按钮约束

状态按协调器的固定枚举/错误码投影，以下名称为交互语义，不要求额外再建立一套字符串状态机。
提示内容使用纯文本，只显示固定文案；原始输出、GUID、口令与本机路径不出现在状态正文或 tooltip。

| 状态 | 可见内容 | 可用动作 |
| --- | --- | --- |
| 地址页空闲 | 原有地址表单 | 连接、换页、关闭 |
| 扫码准备 | 环形进度；“正在准备扫码” | 取消本次、换页、关闭 |
| 等待扫码 | 二维码、倒计时；“等待手机扫码” | 刷新二维码、使用配对码、取消本次、换页、关闭 |
| 正在配对 | 移除二维码；环形进度；“正在配对” | 取消本次、换页、关闭；禁用刷新和重复配对 |
| 确认连接 | 环形进度；“已配对，正在确认连接” | 取消本次、换页、关闭；不显示“连接成功” |
| 已连接 | 成功图标；“设备已连接”；“设备列表已刷新，可返回选择操作设备。” | 完成；“连接另一台”仅在资源已释放后可用 |
| 已配对待连接 | 信息图标；“已配对，连接尚未确认”及续连表单 | 满足续连资格时“继续连接”，或“使用地址连接”、关闭 |
| 扫码过期 | 移除二维码；“二维码已过期，请重新生成。” | 重新生成、使用配对码、关闭 |
| 明确失败 | 失败图标，固定可操作说明 | 按错误类型重新生成/重新配对/使用配对码、关闭 |
| 配对结果不明 | 信息图标；“未能确认配对结果，请检查手机。” | 用户显式重新开始、使用地址连接、关闭；禁止自动重放 pair |
| 取消清理中 | 环形进度；“正在停止，请稍候。” | 关闭可转成 pending close；禁用其他提交和新换页 |
| 已取消且已退出 | “本次操作已停止”；清空二维码与配对码 | 生成二维码/重新配对、换页、关闭 |
| 环境失效且已退出 | “ADB 连接环境已变更，请重新开始配对。” | 重新开始、换页、关闭；无旧会话续连资格 |
| 清理未完成 | “连接任务尚未结束，暂时无法开始新操作。” | “重试停止”、关闭请求；不能解锁新配对 |

进度环只表达忙碌，不使用百分比估算配对完成度。倒计时只表示等待扫码有效期，不是连接成功概率。
结束、隐藏或关闭后停止动画和 UI 计时器。当前阶段改变时更新无障碍描述；不要每秒主动宣布倒计时。

“连接另一台”的实现可以复用“重新生成二维码/重新配对”按钮与原页切换，无须新增第四页。
点击“完成”只关闭窗口，不隐式勾选操作设备、不自动进入应用管理。

### 4.1 已配对待连接的展开区域

在扫码页或配对码页的状态区下方展开，不强制切到“地址与历史”，让用户知道已完成哪一步。

```text
已配对，连接尚未确认
返回手机“无线调试”首页，填写“IP 地址和端口”。
该端口通常与刚才的配对端口不同。

连接地址
[ 192.168.1.10:xxxxx                          ]
                                              继续连接
```

- 只在协调器持有有效的 `PairingContinuation` 时启用“继续连接”；必须保留本轮手机身份验证。
- 若只能确认配对成功但没有 GUID，说明“可以使用地址连接继续”，提供“使用地址连接”进入普通页；
  不把普通连接成功反向宣传为扫码身份已核实。
- 连接地址初始为空；只有服务返回已验证的连接端点才能自动填入。不能从配对地址直接复制其端口。
- 错误在字段下方显示并保留输入；连接失败后允许用户修正地址，再显式重试一次新连接请求。
- 续连期间禁用编辑和重复提交；`PairedOnly` 仍显示已配对，不要求重新扫描。
- 切页、开始另一轮或关闭会清除旧续连资格；界面提示中的已配对不表示撤销手机的既有信任。

### 4.2 错误到行动的固定映射

| 原因 | 界面文案 | 首要行动 |
| --- | --- | --- |
| 找不到所选 ADB | “当前 ADB 客户端不可用，请在设置中检查客户端。” | 用户关闭/回到主窗设置；不显示绝对路径 |
| 不支持无线配对 | “当前 ADB 不支持无线配对，请在设置中选择较新的客户端。” | 设置后重新开始；不提示本机自动安装 |
| mDNS 不可用 | “无法自动发现手机，请尝试使用配对码。” | 使用配对码；手动页不再强制先通过 mDNS |
| 未发现本轮服务 | “未发现扫码设备，请确认无线调试已开启，手机与电脑位于同一局域网。” | 重新生成或使用配对码 |
| 服务冲突 | “发现结果存在冲突，请重新生成二维码后再试。” | 重新生成；不提供“随便连接一个” |
| 配对拒绝/代码错误 | “配对未成功，请检查手机显示的配对码后重新输入。” | 清空配对码并聚焦；扫码页则提示重新生成 |
| 配对超时/未知响应 | “未能确认配对结果，请检查手机。” | 显式重新开始或地址连接；不声称手机未保存信任 |
| 身份不匹配 | “此连接地址与本次配对设备不一致，请核对地址。” | 保留字段供修正，不发布连接成功 |
| 已配对但网络连接失败 | “已配对，连接尚未确认。可填写无线调试首页的连接地址继续。” | 展开续连表单 |

不使用弹出式错误对话框打断每轮。页内结果是扫码和配对码的唯一反馈位置；最终成功不再重复弹一个
全局 Toast。原地址连接仍保留原控制器反馈。

## 5. 刷新、切页、关闭与重开

`AdaptiveNavigation.current_requested` 只提出换页请求，界面提交切页前必须确认旧资源释放。
它的 `set_current()` 可以恢复旧页签，正好复用已有的请求/提交区分。

1. 请求刷新或切页时，立即撤销当前 request_id，清掉可见二维码及配对码，记录一个 pending action。
2. UI 进入“正在停止”，导航、刷新和开始按钮禁用；旧状态信号不能再改正文或触发成功。
3. 只有 worker 真正结束且自有客户端退出后，才执行 pending action：刷新生成新码、切入目标页、
   或保持本页已取消状态。收到普通结果信号或单独的 QThread.finished 都不够。
4. 关闭请求优先级最高，可以覆盖待刷新/待切页；关闭尚未完成时再次关闭只激活同一路径，不创建
   多个停止任务。不要弹“是否取消”的二次确认。
5. 清理超时留在原窗口显示“清理未完成”，继续禁止新配对。重复打开仍激活这个窗口。
   “重试停止”只让原监督器继续收尾，不启动新 ADB 会话。
6. 应用整体退出时由应用监督器统一处理；窗口停止新计时器/动画并跟随关闭结果，不另等不会发出的
   owner 完成信号。界面不能单方面把资源超时包装成关闭成功。

主动点击“取消本次”仅停止本轮，窗口留在当前页；关闭、标题栏 × 和 Escape 则请求清理后关闭。
取消不能暗示撤销手机信任。若配对阶段已开始，在取消完成说明下补充
“手机可能已保存配对记录，可在无线调试中查看。”，不自动发 disconnect、forget 或 kill-server。

环境重检、客户端切换和 ADB 重启准入都会撤销旧会话，包括已经没有活动线程的续连状态。
客户端性能模式变化与普通设备列表刷新不应打断本轮。

## 6. 键盘、主题与高 DPI

- 打开默认页聚焦地址输入；切入配对码页聚焦配对地址；扫码页聚焦当前导航项，不能让隐藏页输入
  保留焦点。错误只聚焦首个需用户修正的输入，不每次进度更新都抢焦点。
- Tab/Shift+Tab 按导航 → 当前页可见输入/动作 → 底部关闭遍历。隐藏页、禁用动作不可达。
  表单 label 设置 buddy，可交互控件有说明用途的 `accessibleName`。
- Enter 只提交当前可见表单的显式启用动作；所有非表单按钮禁用默认自动回车行为，防止扫码时回车
  触发刷新。二维码、状态文本和倒计时不接受键盘输入。
- Escape 与标题栏关闭一致；清理中 Escape 不绕过清理。Ctrl+Tab/Ctrl+Shift+Tab 可在窗口内请求
  前后页，仍走同一延迟切换逻辑。不要假定原生 Pivot 自动提供左右键语义。
- 倒计时、错误与成功同时提供文字，不仅靠颜色。敏感输入不会被整段放进 accessibleDescription。
- 改主题、强调色和 UI 字体时原控件原位更新；不重新生成二维码、不抹掉非秘密输入、不重置会话。
- 测试缩放 100%/150%/200%，字体默认和 22 pt，简体/繁体/英文。使用小屏与最大字体时内容纵向
  滚动，底部动作始终可达，二维码静区不能被裁掉；无需在所有窗口宽度强行展示整个扫码说明。

## 7. 主任务集成约束

1. `gui/dialogs/device_connection.py` 只创建/更新控件与发出意图，不运行 ADB、不 wait 线程、
   不从全局提示文本反推状态。图片字节到 `QPixmap` 的转换只在 GUI 主线程。
2. `adblab/presentation/qt_adb_pairing.py` 负责准入、当前 request_id、pending action 所需的真正
   资源空闲状态、环境失效及 continuation。GUI 状态必须区分“业务结果已收到”和“可再开始”。
3. 可以在窗口内维护 `pending_page/pending_close/pending_refresh` 等简单值；关闭优先，其他 pending
   动作一旦清理开始就不接受叠加。不要为三页窗口添加通用工作流路由器。
4. 协调器至少给视图提供结构化进度、内存二维码、业务结果与资源忙碌/空闲通知。所有跨线程信息带
   request_id；结果与 idle 到达次序不同都必须正确。二维码信号不能经过通用日志/诊断总线。
5. MainFrame 控制单实例、历史快照和最终连接接入。新配对只有经过身份验证的 outcome 才能触发
   `accept_wireless_connection`；旧地址提交继续原方法。只缓存到内存的有效地址或配对字段不得
   顺手加入设置 schema。
6. 状态展示不暴露内部 request_id、设备 GUID、真实设备唯一标识、ADB 绝对路径或命令原文。
   用户主动输入的网络地址可以留在字段供修改，但不要把它重复拼到全局通知和日志中。
7. 新文案补齐现有三种语言并按构建指南生成资源。纯键盘行为和局部尺寸用当前 QApplication/QTest
   测试，不引入 pytest-qt。UI 稳定后才做真实截图验收。
