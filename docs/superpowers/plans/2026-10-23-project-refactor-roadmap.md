覆盖 GUI、Controller、应用用例、models/services、core、持久化与测试/工程组织的全项目依赖审计。
每个领域有明确职责、跨层依赖和资源归属；必要重构按阶段落地并有回归证据、独立审阅及文档。
无必要修改的模块应记录保留依据，不以重写每一行或人为增加抽象作为完成标准。

默认保持公共入口、现有功能和交互、数据路径/格式与平台兼容。既有未提交成果作为前置资产；不自动
commit/push、升级生产依赖、修改 CI/发布、迁移数据、删除功能或操作真实设备。需要上述额外操作时，
先寻找兼容路径；无法避免才按项目授权边界处理。用户数据和密钥不进入审阅/报告。

## 执行和续作

每阶段先形成代码证据、最小设计、冻结接口和分文件实施计划；可独立工作分配给多个 agent，
同一生产文件只交给一个所有者。主 agent 控制共享边界和集成，不让各 agent 重复全量测试。
直接测试通过后按调用链扩大，已通过且未改的集合不重复；真实 UI/设备/产物结论不得由 mock 结果代替。

每阶段的忽略工作区 `.superpowers/sdd/<阶段>/progress.md` 记录基线、任务归属、接口裁定、测试与审阅。
本路线图维护全局已完成/未完成领域。发现跨阶段问题时先记录影响和证据，再安排归属，不在当前改动
中顺手扩散。任何阶段结束后继续下一阶段，只有全项目必要改造和约定验证全部闭环才标记持续目标完成。

项目结构验收单独检查：目录与模块是否对应当前责任，内部依赖是否有清晰方向，大模块是否存在可独立
测试的拆分边界，以及旧路径是否仍有导入/反射/Qt 回调/打包消费者。必要迁移保留公共导入兼容门面，
同步资源解析、PyInstaller 收集、文档和测试；不把纯粹批量改目录名当作结构优化，不搬用户数据或外部二进制。
用户的补充持续纳入同一目标，不能中断或放弃在途任务；当前阶段先集成验收，再衔接目录结构改造。
